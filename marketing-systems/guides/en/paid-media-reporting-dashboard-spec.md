# Paid Media Reporting Dashboard Specification

Define a reporting view that keeps platform delivery, tracked actions, and business outcomes visibly separate.

## When to use it
Use this specification before building an agency or client dashboard that combines ad-platform and first-party data.

## What you need
Stakeholder questions; source systems; event dictionary; spend and revenue definitions; refresh cadence; access rules.

## Workflow
1. List decisions the dashboard must support; remove vanity metrics without a decision use.
2. Define each metric, owner, source, timezone, and update cadence.
3. Separate platform-attributed results from reconciled business outcomes.
4. Specify filters, annotations, missing-data states, and access controls.
5. Review sample screens against real reporting questions before implementation.

## Practical output
A dashboard requirements brief with metric definitions, source map, and review checklist.

## Scope and limits
This is a documentation blueprint, not a working dashboard or a verified connector. Validate access, data quality, and platform terms before implementation.
