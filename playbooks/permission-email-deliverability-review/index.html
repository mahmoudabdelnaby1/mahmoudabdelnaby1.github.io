Permission-Based Email Deliverability Review

Review sender authentication, alignment, message headers, unsubscribe handling, and monitoring against provider-specific evidence.

Open toolkit on GitHub ↗All playbooks
01

When to use it

A team is investigating authentication warnings, spam placement, rejection, or a sender-domain change.

02

Prepare these inputs

Sending domains and providers, message type, recipient-provider volume, current DNS, and sanitized headers from an authorized test message.

03

A practical workflow

  1. 01

    Scope the receiving service, account type, message class, and volume to that provider. Do not conflate Gmail personal with Workspace or Outlook.com with Microsoft 365.

  2. 02

    Inspect SPF, DKIM, and DMARC for the actual sending identity; compare the visible From domain with authentication and alignment results.

  3. 03

    Read results from an authorized received test message and unsubscribe headers where applicable. DNS presence alone does not prove a message passed.

  4. 04

    Review permission source, exclusions, unsubscribes, complaints, and bounces; route legal questions to qualified counsel.

  5. 05

    Record what was and was not tested, assign an owner, and define how findings will be rechecked.

04

What the toolkit includes

A provider-specific reference matrix, sanitized evidence capture, review report, and diagnostic cases.

05

Review boundaries

Provider rules change; verify official guidance for the exact recipient service and message class. Authentication does not guarantee inbox placement.
