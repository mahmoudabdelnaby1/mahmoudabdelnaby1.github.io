IndexNow وBing Webmaster Tools: ما الذي تفعله إشعارات الروابط؟

IndexNow بروتوكول لإشعار محركات البحث المشاركة بأن عنوانًا عامًا أضيف أو تغير أو حُذف. الإشعار يساعد المحرك على معرفة التغيير بسرعة؛ لا يأمره بالفهرسة ولا يضمن ظهور الصفحة في النتائج. قبل دمجه، تأكد من أن الموقع يستضيف ملف التحقق الصحيح وأن النظام يرسل فقط عناوين تغيرت فعلًا.

توضح وثائق IndexNow أن استجابة HTTP 200 تعني استلام الطلب، لا أن الصفحة فُهرست. ويذكر Bing أن الإرسال لا يضمن الزحف أو الفهرسة، وأن على مالك الموقع فحص الحالة والجودة والأخطاء. لذلك افصل بين «أرسلنا الرابط»، «استلمه المحرك»، «زحف إليه»، و«أدرجه في الفهرس». IndexNow: التوثيق الرسمي · Bing Webmaster Tools: بدء استخدام IndexNow · Bing: فحص عنوان URL

اعرف متى يرسل نظامك إشعارًا

ارسل عند نشر صفحة مهمة أو تحديث محتوى يغير فائدتها أو حذف عنوان نهائي. لا ترسل كل زيارة أو تغيير شكلي متكرر؛ الإشعارات يجب أن تعكس تغيرًا حقيقيًا. اسأل المطور أو مزود المنصة: هل يوجد تكامل جاهز؟ هل يعمل عند النشر والتعديل والحذف؟ هل يحترم بيئة الاختبار والروابط غير العامة؟

افحص كذلك ما إذا كان الموقع يرسل IndexNow بالفعل عبر أدوات Bing أو تكامل منصة. إضافة مكوّن ثانٍ فوق تكامل فعّال قد تكرر الطلبات وتزيد الضجيج دون فائدة.

اضبط مفتاح التحقق ومجال العناوين

يتطلب البروتوكول إثبات ملكية المضيف عبر ملف نصي متاح علنًا يحمل المفتاح. يجب أن يتطابق المضيف في الإشعار مع المضيف الذي يثبت المفتاح، وأن يكون كل عنوان مرسل تابعًا للنطاق. لا تضع المفتاح في صفحة خاصة أو شفرة عميل أو تذكرة عامة؛ هو ملف تحقق منشور، وليس سرًا تجاريًا، لكن تجنب نشر بيانات إدارية معه.

راجع ملفات robots وnoindex والـ canonical عند وجود مشكلة اكتشاف، لكن لا تغيّر سياسة الزحف لمجرد زيادة الإشعارات. لا ترسل صفحات تسجيل الدخول أو معاملات البحث أو عناوينًا محذوفة دون سبب تشغيلي موثق.

استخدم Bing Webmaster Tools لفحص النتيجة

بعد الإرسال، راجع لوحة IndexNow وسجل العناوين، ثم استخدم URL Inspection أو Site Explorer لفهم حالة الزحف والفهرسة والأخطاء الظاهرة. إذا لم تُفهرس الصفحة، تحقق من استجابتها، وكونها قابلة للوصول، ومحتواها الأصلي، وcanonical وnoindex والروابط الداخلية. إعادة إرسال الإشعار لا تصلح صفحة ضعيفة أو محجوبة.

احتفظ بسجل فيه العنوان، ونوع التغيير، ووقت الإرسال، والاستجابة، وما ظهر لاحقًا من حالة الزحف أو الفهرسة. لا تخلط نتيجة أداة الويب ماستر بنتيجة بحث فعلية أو ترتيب.

جدول حالات الإرسال

ما تعرفه الدليل ما لا تستنتجه
طلب أرسل سجل الإرسال أو استجابة API أن المحرك فهرس الصفحة
استلم المحرك الإشعار استجابة ناجحة أو سجل اللوحة أنه زحف فورًا
زحف Bing إلى الصفحة حالة زحف في الأدوات أنها ستظهر لكل استعلام
أدرجت في الفهرس فحص الحالة أو نتيجة موثقة ترتيبًا ثابتًا أو زيارة

سكريبت فيديو قصير: الإشعار ليس فهرسة

الخطاف: «وصل رد 200 من IndexNow؟ هذا يؤكد الاستلام، وليس الفهرسة».

القيمة: اعرض التسلسل: نشر/تحديث، إشعار، زحف، تقييم، فهرسة محتملة. اشرح أين تفحص كل حالة في Bing Webmaster Tools.

الخاتمة: «سجّل الإرسال ثم افحص الصفحة، ولا تعد بنتيجة فورية».

كاروسيل تعليمي: خمس نقاط قبل إرسال عنوان

  1. الغلاف: IndexNow يرسل إشعارًا عن تغير الصفحة.
  2. أرسل عند إضافة أو تعديل أو حذف حقيقي.
  3. تحقق من ملف المفتاح والمضيف والعنوان.
  4. راقب الاستلام والزحف والفهرسة كلًّا على حدة.
  5. افحص المحتوى والـ canonical وnoindex إذا لم تظهر.
  6. تذكر: لا يوجد ضمان للفهرسة أو الترتيب.

سلسلة تجربة ميدانية: راقب صفحة منشورة دون إغراق الإرسال

1/ اختر عددًا محدودًا من صفحات جديدة أو محدثة ذات قيمة، وسجّل سبب التغيير.

2/ تحقق من أن تكامل المنصة يعمل وأن ملف المفتاح يطابق المضيف؛ لا تنشئ مسارًا موازيًا قبل معرفة الوضع الحالي.

3/ أرسل الإشعارات وسجّل وقتها والاستجابة والعناوين.

4/ افحص لاحقًا حالة الزحف والفهرسة في Bing، وسجل الأخطاء ومحتوى الصفحة والروابط الداخلية.

5/ قارن سرعة اكتشاف التغيير فقط إذا كانت سجلاتك تتيح ذلك. لا تنسب ترتيبًا أو فهرسة مؤكدة إلى البروتوكول وحده.

حزمة مطالبات محايدة للأدوات: راجع سجل IndexNow

المطالبة 1 — تدقيق المدخلات: «راجع قائمة العناوين [ ] وحدد غير التابع للنطاق أو المتكرر أو غير العام. لا تخترع سبب الإرسال».

المطالبة 2 — تصنيف الحالة: «افصل سجلات الإرسال والاستجابة والزحف والفهرسة بحسب الأدلة الموجودة. علّم الحالات غير المعروفة بدل ملئها بالتخمين».

المطالبة 3 — خطة فحص: «لكل عنوان لم يظهر، اقترح فحوصًا قابلة للتحقق للـ status code وcanonical وnoindex والمحتوى والروابط الداخلية. لا توصي بتغيير robots.txt دون سبب مثبت ومراجعة أثره».

ملف أمثلة: أوقف هذا: وعود الفهرسة الفورية

أوقف: «IndexNow ضمن فهرسة الصفحة فورًا».

استخدم: «أرسلنا إشعارًا؛ سنراجع الزحف والفهرسة حين تتوفر بياناتها».

أوقف: «رد 200 يعني الصفحة ظهرت في Bing».

استخدم: «رد 200 يؤكد قبول الطلب للاستلام بحسب البروتوكول».

أوقف: أرسل كل عناوين الموقع كل يوم.

استخدم: أرسل الروابط التي تغيرت وفق قواعد المنصة، وراقب عدم تكرار الطلبات.

الخطاف والقيمة والقالب: وثّق دورة الإشعار

الخطاف: «هل تعرف الفرق بين إرسال الرابط وفهرسته؟»

القيمة: سجل موحد يمنع تفسير الاستجابة كنجاح بحث، ويساعد في العثور على عطل تكامل أو صفحة غير صالحة.

القالب: «العنوان [ ]. نوع التغيير [ ]. وقت التغيير والإشعار [ ]. طريقة الإرسال [ ]. ملف التحقق والمضيف [ ]. الاستجابة [ ]. حالة الزحف [ ]. حالة الفهرسة [ ]. أخطاء الصفحة [ ]. الإجراء التالي [ ]. ما لا تثبته البيانات [ ].»
