Organize a Content Hub Around a Real User Journey

Connect foundational explanations, task guides and decision resources without creating duplicate pages.

Mahmoud Abdelnaby·7 min read·العربية

A content hub is a map of reader tasks, not a folder of articles sharing a broad keyword. Each page should have a distinct job and a useful path to the next one.

Draw the task map before adding URLs

Start with one audience problem, then map the sequence people need:

Understand the concept → choose an approach → execute the task → diagnose failure → evaluate the result.

For a measurement hub, that could mean: define an inquiry event; test that it fires once; distinguish a click from a received message; then report attribution limits. The pages depend on one another but answer different questions. A single strong page may cover two steps if readers do not benefit from splitting them.

For each proposed page, write its intended reader, exact question, answer, unique evidence or tool, and destination link. Compare it with existing pages. If two pages share the same task and evidence, merge them or choose one canonical answer rather than producing near-duplicates.

Link by next need

Use contextual links where a reader is ready for the next action. Anchor text should say what the destination helps them do. Link Arabic readers to the Arabic equivalent when available. Do not require a reader to move through a fixed funnel if they came with a different task.

Keep the hub governed

Record page owner, sources, review date, language equivalents, and links in a simple map. Check for orphan pages and links that still point to retired routes. Search performance can help identify overlap, but impressions alone do not tell you whether the architecture helps a person finish the task.
