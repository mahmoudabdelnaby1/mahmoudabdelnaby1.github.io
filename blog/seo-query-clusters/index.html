Build SEO Keyword Clusters Around Search Intent

Turn a keyword export into intent-led page decisions, with a rule for when similar queries belong together.

Mahmoud Abdelnaby·5 min read·العربية

A keyword cluster is useful only when it changes a page decision. A list of Arabic spellings grouped under one English translation can merge different markets, buying tasks, and page types. This method keeps the original phrase visible, tests whether queries share a job, and routes each cluster to one page that can actually satisfy it.

Build the evidence row before clustering

Record each raw query, where it came from, market and language register, the task behind it, likely intent stage, existing landing page, and evidence date. Keep raw and normalized spellings side by side. Normalization helps compare hamza, taa marbuta, alef maqsura, and Arabic-Indic digit variants; it does not make two phrases equivalent or prove anyone searches either form.

Decide whether two queries deserve one page

Compare the job, market, offer, and expected page type. If two phrases both seek the same product and the same local offer, one page can cover wording variants naturally. If one asks for price and payment in Egypt while another asks for Saudi stock and installments, a single undifferentiated page may fail both. Check localized search results and existing site pages before splitting; a different wording alone is not a reason to create another URL.

Use this route rule:

  • Existing page satisfies the same task: improve that page and map the variant there.
  • A different task has a different useful answer: consider a separate page only if you can supply distinct, verified content.
  • No offer, market evidence, or operational distinction exists: do not invent a page to capture the query.

Keep the map honest

For each accepted cluster, name one primary page, a handful of supporting phrases, the elements that answer them, and the owner who verifies market facts. Reject literal translations that native speakers would not use, but do not replace them with invented dialect. A human reviewer should check terms with local audience knowledge; platform suggestions are clues, not proof of demand.

After publication, compare page-level impressions, queries, clicks, and meaningful downstream actions by country and language. If two pages repeatedly serve the same task, consolidate the plan before creating more URLs. Google recommends original, people-first value and warns against scaled pages with little added value; keyword coverage by itself is not a reason to publish another page. Turn the map into a page decision

For every proposed cluster, record the dominant task, the evidence that queries share a result type, the page that owns the answer, and the next action a reader needs. Check the live results in the target country and language before combining phrases; a shared word does not establish shared intent. If the evidence is thin, mark the cluster provisional and publish no extra page just to cover a phrase. Revisit the map when Search Console queries or customer language reveal a different task, preserving the old decision in a dated change log.

Search policy note

Google Search warns against generating many low-value pages around query variations; its current AI Search guide says there is no required chunking pattern or ideal page length. Build one useful page per genuine task, not one per wording variation. Google’s AI Search guide · Spam policies.
