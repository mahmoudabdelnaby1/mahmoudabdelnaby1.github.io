Build SEO Keyword Clusters Around Search Intent

Turn a keyword export into intent-led page decisions, with a rule for when similar queries belong together.

Mahmoud Abdelnaby·2 min read·العربية

A keyword list becomes useful only when it tells you whether to create a page, improve an existing page, or leave the query alone. For Arabic MENA work, grouping by English translation alone misses differences in dialect, spelling, and buying task.

Build clusters from a decision, not a shared noun

Start with queries people actually use: Search Console, site search, customer questions, and autocomplete in the target market. Normalize spelling variants for comparison, but keep the original phrase in the record. Do not treat normalization as permission to swap Egyptian, Saudi, Emirati, and Modern Standard Arabic copy as if they were interchangeable.

For each query, record five things: market, wording/register, intent, page that could satisfy it, and evidence. Then ask whether two queries ask the same next question. If yes, test one page for both. If one is looking for price and another for setup instructions, separate them even if both contain the same product term.

Raw phrase Market/register Task Page decision
“مشط حراري لاسلكي” Egypt, colloquial/commercial Compare a product and price Product or category page, if stocked
“cordless heated brush warranty” UAE, English/commercial-support Check after-purchase coverage Warranty/support page, not the product intro

These are illustrative query examples, not measured search-volume claims.

The page decision test

Create or retain a standalone page only when it can answer a distinct task with distinct evidence: local stock or delivery terms, a different service, a different comparison, or a useful procedure. If the only difference is a city name or spelling variant, keep one strong page and explain the variants naturally. A translated page should answer the same underlying task in language a local reader would use; it does not need a literal sentence-by-sentence translation.

For a new cluster, write one proposed page title and one-sentence answer before building the page. If you cannot explain how its answer differs from the closest existing URL, the cluster is not ready for a new page.

Review the result

After publication, compare query impressions and clicks by page and market, then inspect the actual queries. A cluster is a working hypothesis: revise it when Search Console shows different intent or when support questions reveal a missing task. Do not claim that a keyword cluster caused ranking growth from impressions alone.

Google recommends useful, original content and warns against mass-produced pages that add little value. Use the query map to consolidate near-duplicates, not to manufacture URLs: Google Search Essentials and people-first content guidance.
